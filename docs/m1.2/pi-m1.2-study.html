First, four words

Record

A typed persisted fact about an object. A task record describes work, not a chat message.

Row

The SQL representation. Usually a complete serialized record plus indexed mirror columns.

Entry

An immutable transcript event. It may contain model messages, display data, or context controls.

Document

Structured state: an identity and lifecycle, with content reconstructed from bases and deltas.

One request, four atomic commits

ID ≠ commit sequence

Highlighted tables are touched in this commit. Values below are summaries, not full SQL rows. Allocation is shown separately from commit identity.

INFRASTRUCTURE

durable_metadata

The format label and next allocation candidates. One row for the storage namespace. 


            

              Why it exists
              

                ID 1 is reserved for the root. IDs start at 2; commit seq starts at 1. Neither is a
                timestamp or per-table auto-increment. Counters can have gaps. The migration
                reserves the root but does not insert its conversation.
              

            

          

          

            
INFRASTRUCTURE

            
record_ids

            
One immutable global ledger: this number belongs to this record type.

            

            

              Why it exists
              

                Entry 4 and task 4 cannot be different objects. Deferred composite foreign keys
                require a matching claim. Document revisions do not mint new IDs: they use document
                ID + commit seq.
              

            

          

          

            
IDENTITY / IMMUTABLE

            
conversations

            

              The transcript scope. Optional parent ancestry and task ownership are separate edges.
            

            

            

              What is a fork?
              

                A parent edge inherits history through one inclusive entry cutoff. An owner edge
                names the creator task. Forks can be ownerless; owned conversations need not be
                forks. Fork-aware reads follow ancestry rather than copying every entry.
              

            

          

          

            
TRANSCRIPT / IMMUTABLE

            
entries

            

              What happened. Model-facing messages and application-facing data are separate
              payloads.
            

            

            

              Not just chat messages
              

                An entry can be bookkeeping with no model messages. A head marker selects the first
                active-context entry, not the newest message. New entries can omit/replace earlier
                model contributions without rewriting stored history.
              

            

          

          

            
EXECUTION / REPLACEABLE

            
tasks

            
The agent's work: input, definition version, checkpoint, ownership and outcome.

            

            

              States vs outcomes
              

                States: pending, running, waiting, completing, terminal. Successful outcome:
                completed inside terminal state. Checkpoints support resumable progress, not an
                automatic exactly-once guarantee for external side effects.
              

            

          

          

            
ADMISSION / REPLACEABLE

            
submissions

            
A receipt: accepted, placed into the transcript, answered, or left unanswered.

            

            

              Receipt ≠ input entry
              

                Queued input may have no entry. Input goes queued → placed → done, or unanswered.
                Passive writes go queued → done without an answer. Request IDs support
                conversation-scoped retry lookup; Session serializes deduplication, not a unique
                hash constraint.
              

            

          

          

            
STATE IDENTITY / LIFECYCLE

            
documents

            
An incarnation of a typed state object at kind + scope + optional key.

            

            

              Address ≠ incarnation
              

                Retire ID 5, then recreate the same address: it gets a new ID. Session scope uses
                owner 0. A singleton and family member with empty key are different.
                created_at/retired_at are commit sequences, not dates.
              

            

          

          

            
STATE CONTENT / BASE + DELTA

            
document_revisions

            

              Complete snapshots and ordered Chord operation batches, keyed by document ID + seq.
            

            

            

              How reads work
              

                Choose the latest base at or before the target commit. Replay later delta batches in
                order. Definition version is not commit seq. Latest-only history may be pruned;
                rewindable history supports as-of reads.
              

            

          

        

      

      

        
A document read is reconstruction

        

          
BASE · seq 3
{"explained": 0}

          +
          
DELTA · seq 4
[["s", ["explained"], 1]]

          =
          
CURRENT VALUE
{"explained": 1}

        

        

          s is a real Chord “set” operation, not JSON Patch. At seq 3 the value is
          still zero. The document's identity remains 5 at both points.
        

      

      

        
Two kinds of “task,” two runtime APIs

        

          

            
public."Task"

            

              A Kanban card with title, description, assignee and board status. String ID. Use the
              Zod + Effect service in server/tasks.ts, then Prisma Client.
            

          

          

            
agent.tasks

            

              Execution state for model/tool work. Numeric ID. Owned by the durable Storage
              implementation. Agent Prisma models use @@ignore; migration ownership
              does not imply Client CRUD.

          What would PostgreSQL store?
          
// Full record: JSON-encoded TEXT
record = JSON.stringify(task)

// Arbitrary indexed identity: also encoded
kind = JSON.stringify(task.kind)

// Fixed state enum: ordinary text
status = task.state.status

// Read-only, collision-safe SQL lookup
SELECT record FROM agent.tasks
WHERE md5(kind) = md5($1) AND kind = $1
ORDER BY id;

          

            Hash buckets narrow candidates; exact encoded text is the identity. TEXT preserves
            escaped NUL/lone surrogates that JSONB cannot. SQL JSON checks validate syntax, not
            every semantic Pi rule.
